## Open Question: T0a–T0e have no owning execution skill

Same structural gap `US-1.4-task-breakdown.md` already flagged and `plan-reviewer` already accepted for that story: this project's five execution skills are all scoped to a module's own `app/modules/<module>/` files or a migration. None of them own `app/core/config.py`, `app/core/cache_keys.py`, `app/core/security.py`, `.env.example`, or `app/main.py`'s exception-handler registration — all shared/cross-module files. Per this skill's own constraint 4, named here rather than silently assigned to one of the five. Recommendation, consistent with the accepted US-1.4 precedent: treat T0a–T0e as direct, unassisted implementation steps. `plan-reviewer` should confirm this framing before `story-orchestrator` proceeds, same as it did for US-1.4.
