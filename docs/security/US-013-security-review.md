## Advisory Findings (non-§7, does not force Fail)

- **[Low] `event`/`cursor` query params reach the immutable `payload` JSONB unbounded** — `app/modules/audit/router.py:31,35` declares `event: str | None = None` and `cursor: str | None = None` with no `max_length`, unlike `actor_id`/`target_id` (UUID-typed) or `limit` (validated `≤100` in `service.py:116-119`). Any caller holding `audit:read` can pass an arbitrarily long `event`/`cursor` string; `service.py:142-150` writes both verbatim into the self-audit row's `payload` JSONB, which — by this story's own design (OD-19/OD-20) — is never deleted, redacted, or pruned once written (the hash chain in `audit_log_row_hash()` forbids in-place mutation, and `scripts/anonymize_erased_user.py` deliberately does not touch `audit_log`). This is not a §7 violation (no credential, no injection — the value is bound, not interpolated) and doesn't change the verdict, but it's a real unbounded-growth/DoS-adjacent gap in a table designed to be permanent. Secondary effect: `audit_log_row_hash()` SHA-256s the full `payload::text` while the insert trigger holds `pg_advisory_xact_lock` on one global serializing key (`57a978462b74:143`), so an oversized payload extends hold time on a write path this story intentionally serialized for every `audit_log` insert. A two-line fix if judged in-scope: `Query(max_length=64)` on `event` (matching the model's own `event` column, `models.py:36`, `String(64)`) and a reasonable bound on `cursor`. Flagging for `reconciliation-reviewer` rather than fixing here, since it's outside this skill's own scope (advisory, not a §7 rule).
