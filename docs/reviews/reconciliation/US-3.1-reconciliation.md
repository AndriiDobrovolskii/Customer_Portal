# Reconciliation Report: Manage Users (US-3.1 / spec US-3.1)

**Story ID:** US-3.1
**Reviewed:** 2026-09-02
**Overall Verdict:** Pass (initial pass was Fail; 2 gaps found+fixed same-day — see Resolution)

## Summary

All 21 source ACs plus FR-17b/FR-22/FR-23 (no-AC) have a matrix row and a corresponding, passing test. Diffing every test function name the traceability matrix cites against the actual test files found 31 mismatches — the large majority (29) are harmless renames from the matrix's pre-implementation naming to what `test-writer`/`service-and-router-builder` actually shipped (individually verified below, not counted as gaps, mirroring US-2.5's own reconciliation precedent for the identical situation). Two are real: MU-AC9 and MU-AC18 both explicitly name `actor` as a required field on their audit-log row, and neither the unit nor integration test for either AC asserts it — the field is written correctly (confirmed by reading `service.py`/`repository.py`), just never proven by a test. This alone forces the initial verdict to Fail per this skill's own rules (a test that doesn't assert part of an AC's explicit stated behavior). **Resolution:** both gaps were closed same-day (2 new assertions added, no new test functions needed — see Resolution section), gate re-confirmed green, and the verdict is corrected to Pass below.

## Spec Drift

None found. Every status code, error `type` slug, and persisted-state claim in the shipped code matches the approved spec (`docs/specifications/US-3.1-spec.md`, as revised through `planner`'s Architectural Change #4 — `UpdateUserRequest`'s required `reason` field, already reflected in `US-3.1-openapi.yaml` before implementation began, not a coding-time surprise).

## Missing Edge Cases (disclosed, non-blocking — not tied to any numbered AC's explicit text)

- **[Low] Two last-admin boundary unit tests planned in the matrix were never built:** `raise_if_last_admin`'s "target holds admin but is not the last one" and "target holds no admin role at all" branches are proven directly in `test_roles_service.py` (`test_raise_if_last_admin_not_sole_admin_passes`, `test_raise_if_last_admin_non_admin_target_skips_count_query`), but the matrix additionally planned equivalent tests at the `admin_users.service.deactivate_user` call-site level (`test_deactivate_user_admin_not_last_succeeds`, `test_deactivate_user_non_admin_target_skips_last_admin_check`) that don't exist. MU-AC16 itself is fully proven either way (see table above); this would only add belt-and-suspenders coverage at the call site.
- **[Low] A concurrent-`PATCH`/stale-ETag race test (`test_concurrent_patch_stale_etag_race_one_wins`) was planned in the matrix but never built.** No AC or the spec's Enforcement Matrix requires a concurrency proof for `PATCH` specifically (unlike MU-AC16, which the spec's own Enforcement Matrix explicitly flags for a concurrency test) — MU-AC10's stale-ETag rejection is already proven single-request (`test_patch_user_stale_etag_returns_412`).
- **[Low] A dedicated unit-level `q`-matches-both-`email`-and-`display_name` test was planned but not built** — the claim is proven at the integration level instead (`test_list_users_q_matches_display_name_via_trigram_index`), just not also at the unit level the matrix planned.

## Resolution (2026-09-02, same day)

Both Fail-forcing gaps (MU-AC9, MU-AC18) closed by adding the missing `actor`/`actor_id` assertions to the existing test functions — no new test functions needed, matching this project's own "found+fixed same-day" precedent (US-2.5's reconciliation, US-2.6's SPEC_REVIEW, etc.). Full gate re-run green after the fix: 509/509 tests still passing, coverage unchanged at 96.64%.

## Verdict Rationale

Initial pass: Fail — MU-AC9 and MU-AC18 each left one explicitly-named field of their audit-row requirement unasserted, which this skill's own rules treat as a non-asserting test forcing Fail regardless of how minor. Corrected verdict after same-day resolution: **Pass** — every AC now has a matrix row, an existing test, and that test asserts the AC's full stated behavior; no spec drift was found; the three disclosed Missing-Edge-Case items are non-blocking since none leaves a numbered AC's own text unproven.
