# Reconciliation Report: Manage Roles (US-3.2 / spec US-3.2)

**Story ID:** US-3.2
**Reviewed:** 2026-09-01
**Overall Verdict:** Pass

## Summary

All seven Acceptance Criteria (MR-AC1–MR-AC7) have a traceability-matrix row, an existing, behavior-asserting test at both the unit and integration level, and no confirmed drift from the approved spec (`docs/specifications/US-3.2-spec.md`). Two matrix-accuracy gaps were found and fixed during this review: several test function names had drifted from the pre-implementation matrix's planned names (renamed for clarity during T7/T8, never reconciled back), and MR-AC1's own integration test asserted the response and audit log but not its own explicit `perm_epoch is set to now in Valkey` clause — the perm_epoch write was only ever indirectly proven by a *different* AC's test (MR-AC2's). Both fixed before this report: the matrix was updated with every actual test name, and MR-AC1's test now directly reads `perm_epoch_key(target.id)` from Valkey. No AC-level spec drift was found — every FR is implemented exactly as the (already-revised, OD-1/OD-2-incorporating) spec states.

## Spec Drift

No AC-level drift found. Two implementation-time additions were necessary and are already disclosed in the spec itself (not silent):

- **`admin_audit_log` table** — not part of the original DB design (`docs/designs/database/US-3.2-db-design.md`), added during T4 because MR-AC1/MR-AC6 explicitly require it and the table didn't exist anywhere in the codebase yet (belongs to not-yet-built US-3.1). Disclosed inline in `app/modules/roles/models.py`'s `AdminAuditLog` docstring and in `docs/workflow/history.jsonl`'s T4 entry — not a drift from the spec's *intent* (both ACs already state the audit requirement), only from the pre-implementation DB design's omission of the table.
- **`app/modules/roles/dependencies.py`'s `require_scope` factory** — not part of the original API design, which described the scope-check requirement in prose (the API Contract table's `Auth` column) without specifying a mechanism. Disclosed in `docs/designs/api/US-3.2-api-design.md`'s own text at the time and implemented as the natural FastAPI mechanism for that stated requirement — not new behavior, just the code that had to exist to enforce prose the design already committed to.

## Verdict Rationale

Pass: all seven ACs have full matrix coverage, every referenced test exists (confirmed by `grep -n "^async def test_"` against both test files, not assumed from the matrix), and every test asserts the AC's actual stated behavior — several integration tests (MR-AC4's zero-rows-applied check, MR-AC6's full audit-entry proof, MR-AC7's genuine concurrency race) go beyond the minimum bar of "endpoint returned the right status code." The two gaps this review found (a stale matrix and one AC's own persisted-state clause not independently asserted) were both closed same-day, not merely disclosed — the full suite was re-verified green (281/281, gate 7/7) after each fix. No spec drift beyond two disclosed, design-time-omitted-but-spec-required additions.
