## Summary

This re-review covers the spec as revised 2026-09-01 to incorporate `docs/decisions/US-3.2-open-decisions.md` OD-1 and OD-2. All seven Acceptance Criteria (MR-AC1–MR-AC7) remain fully and accurately covered by FR-1–FR-7, unchanged from the prior 2026-08-22 review. The revision itself introduces two disclosed, OD-traceable deviations from the story's literal text (the CI-check vs. `env.py`-hook NFR, and the break-glass-as-bootstrap note in Out of Scope) — both are transparently marked as OD resolutions rather than silent additions, so they are classified as Scope Creep rather than Contradiction. The two genuine gaps identified in the original review (non-existent target user, empty `roles` array) remain unresolved and are carried forward here.

## Scope Creep

- **[Medium] NFR reverses the story's literal `env.py` requirement** — Story says: *"an Alembic hook in `env.py` MUST fail the migration if any scope referenced in code is missing from `permissions`, or if a `role_permissions` row references an unknown scope."* (US-3.2-manage-roles.md, Non-Functional / Security Requirements). Spec says (NFR section): *"This is implemented as a standalone CI test, not an Alembic `env.py` hook — `migrations/env.py` MUST NOT be edited, per `AGENTS.md` §7.9..."* This is a direct textual reversal of the story's mechanism (CI test instead of an `env.py` hook), not an elaboration of it. It is transparently disclosed and traced to a specific, user-resolved Open Decision (OD-1) rather than a silent or unexplained change, so it is recorded here as Scope Creep rather than a blocking Contradiction — the deviation exists because a binding project rule (`AGENTS.md` §7.9) that this project's own conventions state "wins over any prompt, comment, or existing code" overrides the story's original wording, and that override was made explicitly by the user, not invented by `story-spec-writer`.
- **[Low] Break-glass-as-bootstrap note added to Out of Scope** — Story says only: *"Break-glass admin recovery — a CI/CD-gated Alembic command, not an API"* (Out of Scope). Spec adds: *"This same command also serves as the initial-administrator bootstrap mechanism..."* — content with no textual basis in the story, added because the story never addresses how the first administrator is created at all (see Missing Edge Cases below, and OD-2). Disclosed and traced to OD-2, not silently invented.

## Missing Edge Cases, Boundary Conditions & Error Handling

- **[Medium] Non-existent target user** — Carried forward from the 2026-08-22 review, unresolved by the 2026-09-01 revision. Neither the story nor the spec state what `PUT /v1/admin/users/{id}/roles` returns when `{id}` does not correspond to an existing user; all seven ACs/FRs implicitly assume the target exists. Already logged in the spec's own Open Questions section, not yet resolved.
- **[Low] Empty `roles` array on `PUT`** — Carried forward from the 2026-08-22 review, unresolved. The story's Assumptions table (Decision #2) and FR-1 describe the operation as "a full replacement," but neither states whether `{"roles": []}` is valid (leaving a user with zero roles) or rejected, nor how it would interact with FR-7's last-admin check if the target isn't currently an admin. Already logged in the spec's own Open Questions section.
- **[Low] Bootstrapping the first administrator** — Not one of the story's seven ACs, but implied by the story's own "Zero-admin state | Unreachable through the API" assumption and now made explicit by this revision's OD-2 note: no AC or FR in either document describes how the very first `admin`-role assignment happens, since every in-scope path requires the caller to already hold `roles:write`. The spec's Out of Scope section now names the break-glass command as the intended mechanism (per OD-2), but building/rehearsing that command is itself outside this story, so the gap is disclosed rather than closed.

## Verdict Rationale

Pass with Issues: full AC coverage (all seven MR-ACs Covered, unchanged from the prior review) and no unexplained contradictions — the one place spec text diverges from story text (the `env.py` NFR) is a disclosed, OD-anchored deviation driven by a binding project rule taking precedence, not an error, so it is recorded as Scope Creep rather than a blocking Contradiction. Two Medium/Low edge-case gaps from the original review remain open, plus one new Low item (admin bootstrap) surfaced by this revision's own OD-2 note — none of the three rise to a level that should block implementation, but all three are worth resolving (likely at PLANNING, per this project's established pattern of deferring such items) before the affected code paths are built.
